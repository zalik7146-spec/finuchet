# ФинУчет ИИ

Учёт бизнес-расходов в рублях: ИИ извлекает данные из PDF-счетов, сканов чеков и текстовых заметок, пользователь проверяет карточку, запись сохраняется в облако, по текущему фильтру выгружается Excel-отчёт.

## Запуск

```bash
npm install
npm run dev
```

Приложение откроется на http://localhost:3000. Без настроек оно работает в **демо-режиме**: вход не требуется, данные хранятся в браузере, распознавание отключено (доступен ручной ввод).

Продакшен: `npm run build`, затем `npm start`.

## Настройка

Скопируйте `.env.example` в `.env` и заполните.

**Распознавание (Gemini).** `GEMINI_API_KEY` — ключ из Google AI Studio. `GEMINI_MODEL` — имя модели (по умолчанию `gemini-4-hydrogen`). Ключ используется только на сервере.

**Облако (Supabase).** Бесплатный тариф. В `.env` нужны `VITE_SUPABASE_URL` и `VITE_SUPABASE_KEY` (публикуемый ключ, Project Settings → API). Для нового проекта примените `supabase/schema.sql` в SQL Editor.

Вход по умолчанию — по ссылке из письма, без дополнительной настройки. Чтобы включить Google:

1. В Google Cloud Console создайте OAuth-клиент (Web) с адресом возврата `https://<проект>.supabase.co/auth/v1/callback`.
2. В Supabase: Authentication → Sign In / Providers → Google — вставьте Client ID и Secret.
3. Поставьте `VITE_AUTH_GOOGLE=true` и перезапустите сервер.

При размещении не на localhost:3000 укажите адрес сайта в Authentication → URL Configuration. Бесплатный проект засыпает после недели без обращений — его будят кнопкой в консоли Supabase, данные сохраняются.

## Общий реестр и участники

Все участники видят и редактируют один общий реестр. Доступ открывается по почте в разделе «Участники»; человек входит по ссылке из письма на свою почту. Вошедший без записи в списке видит экран «Нет доступа». Сервер распознавания принимает запросы только от участников.

## Размещение в интернете (Render, бесплатно)

1. Выложите проект в репозиторий GitHub (файл `.env` в него не попадает).
2. На render.com: New → Blueprint → выберите репозиторий; настройки берутся из `render.yaml`.
3. Введите в панели Render значения `GEMINI_API_KEY`, `VITE_SUPABASE_URL`, `VITE_SUPABASE_KEY` из своего `.env`.
4. В Supabase: Authentication → URL Configuration → Site URL — адрес сайта на Render. Без этого ссылки из писем ведут на localhost.

Бесплатный сервис Render засыпает после 15 минут без обращений; первое открытие после простоя занимает около минуты.

## Устройство

- `server.ts` — Express: `POST /api/expenses/extract` (multipart: `file` до 15 МБ или `text`, плюс `categories`), вызов Gemini со строгой JSON-схемой, проверка ответа. В dev отдаёт клиент через Vite.
- `src/lib/supabase.ts` — вход (ссылка на почту, Google) и облачное хранилище: таблицы `categories` и `expenses`, синхронизация между устройствами.
- `src/lib/localStore.ts` — хранилище демо-режима с тем же интерфейсом.
- `src/lib/filters.ts` — единый срез `filteredExpenses`: от него считаются KPI, графики, таблица и экспорт.
- `src/lib/excel.ts` — три листа: «Сводка по направлениям», «Детальный реестр», «Динамика по периодам»; формулы SUM/SUMIF, формат `#,##0.00 "₽"`.
- `supabase/schema.sql` — таблицы, проверки значений и список участников и политики RLS: данные доступны только участникам.

## Ограничения

- В демо-режиме (без ключей Supabase) распознавание не требует входа — не размещайте приложение в интернете в таком виде.
- Исходные файлы не сохраняются — в базу попадают только поля расхода, имя и тип файла.
