# Дизайн: экран проверки счетов и дашборд — краткий проект

Дата: 2026-11-17 · Согласовано пользователем в переписке («начнём со счетов и дашборда, остальное по пути»).

## Зачем

Счета на комбинате приходят на 10–30 позиций. На экране проверки каждая позиция занимает 3–4 яруса по высоте, окно узкое, название позиции обрезается, а предупреждение о дубле стоит в самом низу — под всеми строками. На дашборде верх экрана занимает крупная зона загрузки, а иерархия в показателях слабая.

## Что делаем

**Экран проверки**
1. Окно шире — почти на весь экран (до 1280 px).
2. Позиция — компактная строка: поле названия, поле товара, количество с единицей, сумма, цена за единицу, удаление. Под ней одна мелкая служебная строка: «в документе: 10 меш» слева и «новый товар · кг ▾ · не товар» под товаром. Подсказка о цене — во всю ширину строки, а не в узкой первой колонке.
3. Предупреждение о дубле — баннером вверху карточки расхода, до полей.
4. Сводка над таблицей позиций одной строкой: «N позиций · K новых товаров · M дороже прошлой закупки · сходится с итогом / не сходится на X ₽».
5. Название контрагента сокращается при распознавании: «Общество с ограниченной ответственностью "СОФИЯ"» → «ООО «СОФИЯ»» (ООО, АО, ПАО, ЗАО, ИП).
6. Служебные имена файлов (uuid, хэши) не показываются — вместо них тип источника.

**Дашборд**
7. Зона загрузки — одна компактная полоса: «Загрузить счёт» + поле заметки + «Распознать» (перетаскивание файла по-прежнему работает на всей полосе).
8. Показатели: подпись и сравнение читаемее (13 px), главное число чуть меньше (22 px), изменение к прошлому периоду — отдельной строкой.

## Подходы

Обсуждали только как сделать, вариантов по сути не было: правки внутри текущей визуальной системы (Tailwind, светлый реестр, без цветных «пилюль»). Отклонено: модальное окно → отдельная страница проверки (больше переделок, теряется контекст дашборда) — можно вернуться, если широкого окна не хватит.

## Не цели

Реестр, «Товары», «Направления» — «по пути», отдельным шагом. Логику распознавания и сохранения не меняем.

## Решения исполнителя

- Сокращение ОПФ — на сервере при распознавании (так в базе сразу короткое название) и в проверке дублей уже есть нормализация.
- «Служебное имя файла» — имя без расширения из 16+ символов, состоящее только из 0-9, a-f и дефисов.
